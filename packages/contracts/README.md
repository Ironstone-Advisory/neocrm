# Executable contracts

Generated TypeScript projections of [`spec/contracts/capabilities/cap-001.schema.json`](../../spec/contracts/capabilities/cap-001.schema.json), the bounded [`spec/contracts/agent-runtime.schema.json`](../../spec/contracts/agent-runtime.schema.json), the planned [`spec/contracts/governed-action.schema.json`](../../spec/contracts/governed-action.schema.json) experimental authority scaffold, and the host-neutral [`spec/contracts/workflow-definition.schema.json`](../../spec/contracts/workflow-definition.schema.json) workflow discovery/orchestration scaffold.

The CAP-001 schema is normative only for relationship-brief exchanges. The agent-runtime schema validates the thin EXP-001 reference path, including AgentDefinition, AuthorityGrant, Trigger, Goal, Plan/PlanStep, AgentRun, Handoff, PolicyDecision, ContextSnapshot, Outcome, LearningSignal, and AuditEvent. The governed-action schema makes non-delete WriteGrant and separate exact DeletionAuthorization shapes testable, but no action gateway implements them yet. WorkflowDefinition describes a reusable, versioned job and governance envelope; it is distinct from a Plan instantiated for one Goal and from a PlaybookDefinition containing reusable guidance. Its generated contract does not implement routing, scheduling, connection registration, or action execution. None of these schemas is the complete NeoCRM ontology or full production Agent layer.

Run `pnpm generate:contracts` and `pnpm generate:workflows` after changing their normative sources; do not hand-edit generated TypeScript or generated workflow capsules.

`workflow-conformance.mjs` is the reusable semantic acceptance layer above JSON Schema. It resolves internal and specification references, preserves the Recommendation/epistemic boundary, enforces source-read and governed-action lifecycles, checks honest evidence status, and exposes the same fail-closed run-fixture checks used by tests. `pnpm validate:workflows` applies it to the complete generated registry.
